# 系统架构

## 1. 项目名称

**选题二：交易所钱包系统 DApp 开发**

## 2. 项目目标

本系统实现一套基于以太坊测试链的交易所钱包系统 DApp，用于模拟数字资产交易所中用户充值、提现、资金归集、热冷钱包隔离、提现风控、多重签名审批、资产账本和链上对账等核心流程。

系统使用 MockUSDT 作为测试资产，使用 Foundry Anvil 作为本地区块链网络。系统不处理真实资产，不实现交易撮合、K 线、订单簿、真实 KYC 或真实主网资金托管。

## 3. 系统边界

### 3.1 前端负责

前端负责展示、交互、路由、表单体验、钱包连接和状态呈现，包括：

1. 用户资产展示。
2. 用户充值地址和二维码展示。
3. 用户提现申请表单。
4. 充值、提现、归集、审批、对账等操作状态提示。
5. 管理员风控看板展示。
6. 管理员多签审批页面。
7. 链上全量事件查询页面。
8. MetaMask 钱包连接和网络状态展示。

前端不能承担影响资产正确性的核心业务规则。余额变更、充值入账、提现风控、多签审批、对账结果均以后端与链上数据为准。

### 3.2 后端负责

后端负责业务规则、资产账本、区块扫描、风控判断、交易构造、交易广播、审计记录和数据一致性，包括：

1. 连接以太坊节点。
2. 调用智能合约。
3. 创建用户和充值地址。
4. 扫描链上 ERC20 `Transfer` 事件。
5. 处理充值确认数和幂等入账。
6. 管理用户资产账本。
7. 处理提现申请和风控校验。
8. 广播普通提现交易。
9. 管理大额提现多签流程。
10. 执行资金归集。
11. 执行资产对账。
12. 生成储备金证明。
13. 将审计摘要哈希写入链上。
14. 提供 REST API 给前端调用。

### 3.3 智能合约负责

智能合约负责链上资产流转、充值地址创建、多签冷钱包审批和审计锚定，包括：

1. 测试代币发行和转账。
2. 用户独立充值地址创建。
3. 充值钱包资产归集。
4. 大额提现多签审批和执行。
5. 对账快照与储备金证明哈希上链。

### 3.4 数据库负责

数据库负责记录链下业务状态和本地资产账本，包括用户信息、充值地址、充值记录、提现记录、账本流水、风控记录、扫描区块状态、对账报告和多签审批记录。

链下数据库不是最终资产真实性来源。资产真实性通过链上交易、链上余额、本地账本和对账审计共同校验。

## 5. 核心模块

### 5.1 合约模块

| 合约 | 职责 |
|---|---|
| `MockUSDT.sol` | 测试 ERC20 代币，用于模拟交易所支持的数字资产 |
| `DepositWallet.sol` | 用户独立充值钱包，接收充值并支持归集到热钱包 |
| `DepositWalletFactory.sol` | 为用户创建独立充值钱包并记录映射关系 |
| `MultiSigColdWallet.sol` | 冷钱包多签合约，用于大额提现审批和执行 |
| `AuditAnchor.sol` | 保存对账快照哈希、Merkle Root 和储备金证明摘要 |

### 5.2 后端模块

| 模块 | 职责 |
|---|---|
| `routes` | 接收 HTTP 请求，返回统一响应格式 |
| `schemas` | 参数校验、DTO 定义和响应类型定义 |
| `services` | 业务编排，包括充值、提现、风控、对账、归集等 |
| `repositories` | 数据库访问，不包含业务规则 |
| `jobs` | 区块扫描、充值确认、自动归集、定时对账等后台任务 |
| `core` | 配置、错误码、日志、链连接、合约实例等基础能力 |
| `utils` | 地址处理、金额换算、哈希、Merkle Tree 等工具 |

### 5.3 前端模块

| 模块 | 职责 |
|---|---|
| `app` | Next.js 路由和页面入口 |
| `features/user-assets` | 用户资产、充值、提现、历史记录 |
| `features/admin-dashboard` | 管理员资金池、风控、多签、对账、链上数据 |
| `components` | 通用 UI 组件 |
| `hooks` | 钱包、API 请求、交易状态等可复用 hooks |
| `services` | 前端 API 请求封装 |
| `types` | 前后端共享的 TypeScript 类型 |

## 7. 核心业务流程

### 7.1 用户创建与充值地址分配流程

```text
用户进入系统
→ 前端连接钱包
→ 前端调用 POST /api/users
→ 后端创建用户记录
→ 后端生成 userIdHash
→ 后端调用 DepositWalletFactory.createWallet(userIdHash)
→ 合约创建 DepositWallet
→ 后端保存充值地址
→ 前端展示充值地址和二维码
```

### 7.2 充值监听与确认入账流程

```text
用户向充值地址转入 MockUSDT
→ 区块产生 Transfer 事件
→ BlockScanner 扫描新区块
→ 后端识别 to 地址是否属于系统充值地址
→ 创建 PENDING 充值记录
→ 达到确认数后更新为 CONFIRMED
→ 写入 ledger_entries
→ 增加用户可用余额
→ 前端展示充值成功
```

### 7.3 资金归集流程

```text
管理员进入归集页面
→ 后端查询各充值地址链上余额
→ 管理员选择归集或一键归集
→ 后端调用 DepositWallet.sweep(token, hotWallet)
→ 充值钱包资产转入热钱包
→ 后端记录归集流水
→ 前端刷新热钱包余额
```

### 7.4 提现风控流程

```text
用户提交提现申请
→ 后端校验地址格式和金额
→ 后端查询用户可用余额
→ RiskEngine 执行黑名单、限额、频率、大额规则
→ 风控通过：进入提现处理
→ 风控命中：进入拒绝、人工审核或多签审批
```

### 7.5 普通提现流程

```text
风控通过且金额低于大额阈值
→ 冻结用户余额
→ 热钱包发起 MockUSDT 转账
→ 返回 txHash
→ 交易确认后扣减冻结余额
→ 写入 ledger_entries
→ 前端显示提现成功
```

### 7.6 大额提现多签流程

```text
提现金额超过大额阈值
→ 后端冻结用户余额
→ 后端调用 MultiSigColdWallet.submitWithdrawal
→ 管理员 A 审批
→ 管理员 B 审批
→ 达到 2/3 阈值
→ 调用 executeWithdrawal
→ 冷钱包向目标地址转账
→ 更新提现状态和账本流水
```

### 7.7 资产对账与审计上链流程

```text
管理员触发对账
→ 后端统计本地用户资产负债
→ 后端查询热钱包、冷钱包、充值钱包链上余额
→ 计算差额和储备率
→ 构造 Merkle Tree
→ 生成 merkleRoot 和 snapshotHash
→ 调用 AuditAnchor.anchorSnapshot
→ 前端展示对账结果和上链交易哈希
```

## 8. 关键约束

### 8.1 安全约束

1. 不允许在前端保存私钥。
2. 后端私钥只能出现在 `.env`，不得写入代码、日志或提交仓库。
3. 本项目所有私钥仅允许使用 Anvil 测试私钥。
4. 管理员操作必须校验钱包地址或管理员身份。
5. 大额提现必须进入多签审批。
6. 黑名单地址提现必须被拦截。
7. 用户余额不足时不能提现。

### 8.2 幂等约束

1. 充值事件唯一键为 `chainId + txHash + logIndex`。
2. 重复扫描不能重复入账。
3. 同一提现请求不能重复广播。
4. 同一多签审批人不能重复审批同一请求。
5. 对账快照不能重复上链同一 `snapshotHash`。

### 8.3 数据一致性约束

1. 所有资产变动必须写入 `ledger_entries`。
2. 用户余额不能只通过修改余额字段完成，必须有流水支撑。
3. 提现必须先冻结余额，再执行链上交易，最后确认扣减。
4. 对账结果需要同时展示本地负债、链上储备和差额。

### 8.4 可观测性约束

1. 区块扫描需要记录扫描高度。
2. 充值、提现、归集、审批、对账均需要日志。
3. API 错误必须返回统一错误结构。
4. 前端必须展示 loading、empty、error、success、permission 状态。

### 8.5 部署约束

1. Anvil 本地链必须完整支持所有业务流程。
2. Sepolia 部署脚本必须可配置。
3. Mainnet-ready 脚本只作为部署能力展示，不承载真实资产。
4. README 必须说明启动顺序和环境变量。
